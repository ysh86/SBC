# Pico + MC68008 bus firmware

Raspberry Pi Pico/RP2040 が外付け MC68008 に ROM、RAM、USB CDC UART を提供するための Pico SDK ファームウェアです。

## Pin map

| Pico GPIO | Direction | Signal |
| --- | --- | --- |
| 0-15 | in | A0-A15 |
| 16-23 | in/out, PIO controlled | D0-D7 |
| 24 | in | /DS |
| 25 | in | R/W |
| 26 | out | High固定（/ASは未使用） |
| 27 | out | /DTACK, held low |
| 28 | Low出力/Hi-Z入力 | /RESET and /HALT |
| 29 | out, PIO controlled | CLK, 10MHz MPU clock |

Standard Pico boards do not bring every GPIO in this table out as a normal header pin. This pinout is most natural on a bare RP2040 or a board that exposes GPIO24 and GPIO29.

MC68008 の A16 以降は接続しないため、MPU から見えるアドレス空間は 64KB です。

## Memory map

| MPU address | Function |
| --- | --- |
| `$0000-$ffef` | RAM |
| `$fff0` | 6850-like status register, writes ignored |
| `$fff1` | 6850-like data register |
| `$fff2-$ffff` | Reserved I/O, writes ignored |

The MPU-visible memory image is one 64KB SRAM-resident initialized array. `rom_image.h` supplies its initial contents starting at `$0000`, and the I/O area at `$fff0-$ffff` is initialized to `$ff`. The bus loop treats `$0000-$ffef` as writable RAM and reserves `$fff0-$ffff` for I/O.

```c
static uint8_t memory[64 * 1024] __attribute__((section(".data.memory_image"), aligned(4), used)) = {
#include "rom_image.h"
    , [0xfff0 ... 0xffff] = 0xff,
};
```

Replace `src/rom_image.h` with comma-separated hex bytes. Offset `$0000` in that file maps to MPU address `$0000`; unspecified bytes are initialized to zero.

## UART status bits

The `$fff0` read status register only exposes the two MC6850-compatible flow bits needed by the bus loop:

| Bit | Meaning in this firmware |
| --- | --- |
| 0 | RDRF: USB-to-MPU SIO FIFO has at least one byte |
| 1 | TDRE: MPU-to-USB SIO FIFO is not full |

This maps directly to RP2040 `sio_hw->fifo_st & 0x03`, so the hot path reads the UART status with one SIO register load plus a two-bit mask. Writes to `$fff0` are ignored. Interrupt output, DCD/CTS, and overrun status are not implemented.

## Timing model

Core 1 is dedicated to the MPU bus loop and waits for /RESET to be released before entering it. Core 0 waits about one second after USB initialization, writes the USB CDC banner if a host is connected, and then releases /RESET by changing GP28 from Low output to Hi-Z input. The external pull-up then raises the shared /RESET and /HALT net. If USB CDC is not connected, the banner is skipped and reset is still released, so the MPU can start without a USB host. As an initial MC68008 conversion, the loop uses /DS on GP24 in place of the former E-cycle test: it waits for /DS to go low, samples address and R/W via `sio_hw->gpio_in`, decodes only the two ACIA read addresses before falling through to `memory[address]`, and services the loop from SRAM-resident code. On MPU write cycles, the bus core waits for /DS to return high, then samples GPIO16-23 from that same snapshot before committing RAM or ACIA data writes. /AS is not used or connected; GP26 is configured as an output held High. /DTACK is held asserted.

## Reset wiring

Connect the MC68008 /RESET and /HALT pins together and to GP28. Pull this shared net up to **3.3 V** with 4.7 kΩ. Do not pull it up to 5 V because RP2040 GPIO pins are not 5 V tolerant. The firmware emulates an open-drain reset driver: it asserts reset by driving GP28 Low and negates it by disabling the output driver. The internal GPIO pulls remain disabled.

The data GPIOs are assigned to PIO, not SIO. The data bus uses three PIO state machines: one continuously accepts low-byte values and writes GPIO16-23, one controls GPIO16-19 directions, and one controls GPIO20-23 directions. On each read cycle the bus core pushes only the data byte to the value SM, whose one-instruction `out pins, 8` loop uses autopull and stalls while the TX FIFO is empty. The two 4-bit direction SMs watch /DS and R/W directly; when /DS is low and R/W is high they drive their nibbles, then release GPIO16-23 to input/Hi-Z when /DS rises. This avoids bus contention on the next write cycle.

GPIO29 CLK output is generated by PIO. The firmware raises the RP2040 core voltage to 1.15V, sets `clk_sys` to 240MHz, and the PIO clock program produces a 10MHz clock with 12 system cycles per half-period.

## Build

Install and export the Pico SDK in the usual way, then build:

```sh
export PICO_SDK_PATH=/path/to/pico-sdk
cmake -S . -B build -DPICO_BOARD=pico
cmake --build build
```

The UF2 will be generated as:

```text
build/pico_mpu_68008.uf2
```

For timing validation, build with optimization enabled and check CLK, GP24 /DS, R/W, /DTACK, and GPIO16-23 on a logic analyzer. Also confirm that GP26 remains High. The firmware is structured for the requested clock rate, but the final margin depends on the exact board, wiring, level shifting, and MPU timing.
